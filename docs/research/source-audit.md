The first release includes ten user-invoked stages, including `setup-devcraft`. The adapter installs it with the collection before the developer invokes it; an undiscovered skill cannot install itself. Setup now asks which instruction file(s) to configure and whether to use local Markdown or GitHub Issues. Of the specialists, retain `visual-taste` because direction, frontend implementation, and UI review can request the same bounded aesthetic check. **Do not create a separate `design-principles` skill in the first release**: its hierarchy, semantics, states, responsive and accessibility checks can live as on-demand references owned by `design-direction` and `ui-review`. This avoids a third visual authority and one more always-visible skill description. The selected inventory and trade-offs are approved and implemented.

## Agent Skills format and agent compatibility

The [Agent Skills specification](https://agentskills.io/specification) requires a skill directory with `SKILL.md`, YAML frontmatter `name` and `description` (name matches the directory; 1–64 lowercase alphanumeric/hyphen characters, no consecutive hyphens), and permits optional references, scripts, assets, `license`, `compatibility`, `metadata`, and experimental `allowed-tools`. It recommends concise instructions, on-demand resource loading and relative paths. It does **not** standardize discovery paths, strict user-only invocation, cross-skill dependency resolution, or `AGENTS.md` behavior.

| Host | Documented discovery and explicit use | User-only control and project guidance | Evidence level |
| --- | --- | --- | --- |
| Codex | [Build skills](https://learn.chatgpt.com/docs/build-skills): project `.agents/skills` from working directory to repository root; explicit `$skill` or CLI/IDE skill picker. | `agents/openai.yaml` `policy.allow_implicit_invocation: false` is Codex-specific. [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) loads along the project path. | Official docs inspected; installed Codex CLI `0.162.1` help inspected. No DevCraft activation test yet. |
| Claude Code | [Skills docs](https://code.claude.com/docs/en/skills): project `.claude/skills/<name>/SKILL.md`, explicit `/name`; model activation normally allowed. | `disable-model-invocation: true` is Claude-specific. Current [memory docs](https://code.claude.com/docs/en/memory#agentsmd) say Claude Code 2.1.277+ can read `AGENTS.md` directly when no project `CLAUDE.md` supersedes it; otherwise use an `@AGENTS.md` import or setting. On Windows, prefer import over a symlink. | Official docs only; no Claude runtime test. |
| Cursor | [Skills docs](https://cursor.com/docs/skills): `.agents/skills` and `.cursor/skills`, including nested directories; explicit `/name`, model activation normally allowed. | `disable-model-invocation: true` is Cursor-specific. [Rules docs](https://cursor.com/docs/rules) support root and nested `AGENTS.md`. | Official docs only; no Cursor runtime test. |

The source repository's `skills/user-invoked` / `skills/model-invoked` grouping is **not** an installation path. An adapter must materialize each skill directory under the target host's discovered root, add only verified metadata, preserve support-file relative paths, and avoid duplicate installations. `.agents/skills` is a documented shared project path for Codex and Cursor; Claude Code needs `.claude/skills` even when it can read `AGENTS.md`. Host metadata is optional at source, mandatory where strict explicit invocation is claimed. A body instruction is only a best-effort gate in an untested host. Codex documentation also describes a context budget for surfaced skill descriptions, so overlapping specialist names/descriptions should be pruned before packaging.

## Licensing boundary

The audit records licenses and source paths so implementation can write original DevCraft instructions or properly licensed adaptations. No upstream skill text or runtime has been copied into DevCraft at this phase. A root license is insufficient evidence that every bundled third-party asset can be redistributed; those assets need separate checks before inclusion.
